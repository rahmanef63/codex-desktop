different techstack.

Root causes worth not rediscovering:

- `collaboration` namespace is flattened by the gateway's Responses→Chat translator for
  non-OpenAI upstreams → sub-agents die with `unsupported call: collaboration`. A capture
  carried 6 members; the binary declares **at least ten** (see the correction in
  `capability-matrix.txt`), so a gateway fix that special-cases six names is incomplete.
- **Images through a non-OpenAI upstream are unstable, and the earlier mechanism was wrong.**
  This document used to say the model swaps to `kimi-k2.7-code` and the base64 is tokenised as
  text. Neither reproduced on 2026-11-01: `kimi` appeared 0 times, no `prompt too long`, and
  `input_image` was present in the rollout. What actually happens is that `ctx/*` receives the
  image, can even name the marker, then degenerates — 2 of 3 runs ended with **no answer at
  all** (one at 10.9k tokens after calling `view_image`, one at 256k in a loop). `cx/*` answered
  3 of 3 at ~17.3k tokens. Advice unchanged: **use `cx/*` for anything with an image.** The
  reason is instability, not a model swap. Details: `PROGRESS.md` §5i.
- Windows sandbox banner ("Couldn't check Windows setup") is cosmetic.
  `HKLM\SOFTWARE\OpenAI\Codex\WindowsSandboxService` binds provisioning to one `CODEX_HOME`.
  Do not edit that registry key; it strips the sandbox from the real account.
- `Access is denied (os error 5)` on plugin cache = `chrome@openai-bundled` enabled in the clone.
  Chrome launches `extension-host.exe` from inside the cache directory and Windows locks it.

Two operational rules learned the hard way, now enforced in code:

- **`--sandbox workspace-write` silently becomes `read-only`** when `CODEX_HOME` is not the
  registered home. It is the same one-home provisioning as the banner, from another direction.
  The symptom is `apply_patch` failing while the model reports success. The 9router side of the
  probes therefore runs `danger-full-access`, which is how the clone actually runs.
- **Probes must not write into the real account.** `codex-caps-quicktest` was appending a
  rollout to `~/.codex/sessions` per probe (209 → 366 files in one session). The 9router side
  now uses `CODEX_HOME=~/.codex-probe`. The chatgpt side cannot move — it needs that home's
  `auth.json` — so it still adds to the real history, by necessity, not oversight.
