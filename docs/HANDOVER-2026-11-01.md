## The split, and why

Rahman's decision on 2026-11-01: **do not make them alike.** Two repositories, same scope,
different techstack.

- **codex-desktop** — configuration and tooling for OpenAI's Codex Desktop (Rust + Electron).
  Is not, and will not become, a clone of that binary; it drives the real one.
- **codex-web** — SvelteKit console. Not an agent. Execution reaches the user's machine only
  through the bridge in `docs/terminal.md` / `bridge/terminal-bridge.mjs`.

The origin of the confusion: the web UI was reconstructed from **screenshots** of the desktop
app, and much of it was reconstructed wrongly. Do not treat the existing views as a spec.

Two traps found the hard way:

- Setting the only stub backend's `ready` to `false` to stop the console claiming a device also
  makes `initialBackend()` return `""`, so no backend is selected and the composer can never send.
  Honesty belongs in `stub: true` + `reason`, not in `ready`. Caught by `dev-smoke`, not by unit
  tests — nothing unit-tests the shell→composer path.
- `Chat.svelte` reads a provider key from `localStorage.getItem("byok-key")`, which contradicts
  `docs/byok.md` §1 ("the browser never holds a provider key"). Nothing writes that key, so the
  SvelteKit BYOK path always fails its `parseChat` validation today. **Still unfixed.**
